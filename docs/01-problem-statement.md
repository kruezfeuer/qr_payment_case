# Описание проблемы

## Контекст

Рост количества безналичных операций требует предоставления клиентам и торговым точкам удобных способов оплаты.

Одним из распространённых сценариев является оплата покупки с использованием QR-кода.

Для торговых точек важно иметь возможность быстро сформировать платёжный запрос, предоставить клиенту удобный способ оплаты и получить подтверждение успешного проведения операции.

---

## Проблема

Существующие процессы оплаты требуют взаимодействия нескольких участников:

- торговой точки;
- клиента;
- банковского приложения;
- платёжной инфраструктуры.

При отсутствии единого сервиса управления QR-платежами возникают сложности:

- получение актуального статуса платежа;
- обработка повторных запросов;
- контроль жизненного цикла операции;
- информирование торговой точки о результате.

Необходимо разработать сервис, который обеспечит полный цикл обработки платежа по QR-коду.

---

## Цель проекта

Создать сервис приёма платежей по QR-коду, который позволит:

- торговым точкам создавать платёжные запросы;
- формировать QR-коды для конкретных покупок;
- клиентам выполнять оплату через банковское приложение;
- получать подтверждение результата операции;
- сохранять информацию о платежах.

---

## Бизнес-ценность

Реализация сервиса позволит:

- повысить удобство оплаты для клиентов;
- сократить время проведения операции;
- обеспечить прозрачность статусов платежей;
- уменьшить количество ошибок при обработке операций;
- создать основу для дальнейшего развития QR-платежей.

---

## Критерии успеха

Проект считается успешным, если:

- торговая точка может создать платёжный запрос;
- клиент может выполнить оплату по QR-коду;
- сервис корректно обрабатывает успешные и неуспешные операции;
- торговая точка получает результат оплаты;
- клиент может получить информацию о выполненной операции.

---

## Ограничения

В рамках MVP:

- поддерживается оплата одной покупки одним клиентом;
- QR-код связан с конкретным платёжным запросом;
- операция выполняется онлайн;
- возвраты денежных средств не входят в первую версию;
- поддерживается только один тип платежного сценария.

---

## Не входит в текущий объём

В рамках MVP не реализуются:

- возвраты;
- частичная оплата;
- разделение платежа;
- программа лояльности;
- рассрочка;
- офлайн-оплата.
